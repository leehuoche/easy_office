# easy_cooker：小餐厅后厨动态调度模型

本文档集记录问题定义、数学模型和评价方案，作为后续仿真与算法实验的基础。当前阶段不开发点餐系统，不讨论界面、交互和系统接入。

目标场景为同时接待约二三十位顾客及以下的小餐厅，具体桌数和厨师数作为参数，不作为固定常数。此处将“二三十人”暂按同时用餐人数理解，后续可调整。

## 核心问题

在不预知未来订单和加菜的情况下，为有限厨师选择下一批制作任务。首菜遵守首次下单顺序，并满足最大等待要求；首菜之后允许跨桌穿插，兼顾后续等待、整桌完成和同菜合做收益。

首菜公平与时限可能冲突，因此模型必须允许报告无可行解。排菜能够重新分配等待、利用合做减少工作量，但不能保证在任意客流下兑现服务承诺。

## 当前状态

- 已形成概念模型和实验设计，并实现标准库HTTP原型、简单调度器、模拟时钟演示与测试；尚未实现优化求解器和批量评价仿真器。
- 文档中的数值示例均为说明用途，不是门店实测结果。
- 不预设系统一定提升翻台率；先验证直接等待指标，再扩展到用餐和等位模型。

## 快速运行

Python 3.9及以上，无第三方依赖。在本目录执行：

```bash
python3 demo.py
python3 main.py --chefs 2 --tables 8
python3 -m unittest discover -s tests -v
```

完整接口说明和限制参见[第一版实现与运行](./04_implementation.md)。
